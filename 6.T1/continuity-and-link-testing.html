Continuity and link testing

Testing answers three questions in order. Does the fiber go where the paperwork says (continuity)? Does it lose less light than its budget (insertion loss)? Does the live link come up clean on the right kind of cable (link status)?

Exam objectivePerform cable continuity and link testing (optical power meter, link status, differentiate between NVIDIA vs. non-NVIDIA cabling).

In one minute

  • Continuity / polarity: trace each fiber end to end with a visual fault locator (VFL), visual tracer or OLTS. This confirms routing, polarity and that labels match the records.
  • Insertion loss: an OLTS (light source + optical power meter) with good reference cords. Multimode at 850/1300 nm, single-mode at 1310/1550 nm. Compare against the link's loss budget.
  • OTDR locates events (connectors, splices, bends, breaks) along the fiber, but isn't the tool for measuring total cable loss.
  • Live link: port LEDs, link state (ibstat, iblinkinfo, l1-show/ethtool) and transceiver DDM (Tx/Rx power per lane), then error counters.
  • NVIDIA vs non-NVIDIA: read the module EEPROM (vendor, part number) via mlxlink -m / switch transceiver commands, and check against the validated list. The Cable Validation Tool (CVT) compares the fabric to the plan.

The test toolkit

VFL / visual tracer

Bright red laser shows which fiber lights up at the far end, and glows at breaks or tight bends in jacketed fiber. Use it for continuity and polarity.

Light source + power meter (OLTS)

Measures insertion loss of the installed plant against a reference. A calibrated meter also reads a transmitter's actual output.

OTDR

"Optical radar": length, the location and loss of each connector and splice, bends and breaks. Use long launch/receive cords. Needs a trained operator.

Inspection scope

100–200× (video preferred) before every test and mating. Dirty references ruin results.

Switch / host tools

Port LEDs, link state, DDM Rx/Tx power per lane, FEC and error counters, module EEPROM identity.

Cable Validation Tool

NVIDIA's CVT (with UFM) checks the cabled fabric against the intended topology and flags wrong or unsupported cables.

Insertion-loss test (OLTS)

Reading Rx power

Transceivers report Tx and Rx optical power per lane (DDM/DOM), in mW or dBm. dBm = 10 × log10(mW). Check every lane: one dark lane takes the whole link down.

−30 dBmalarm · warn · normal · warn · alarm+6 dBm

Thresholds here are illustrative for a short-reach module. Per NVIDIA's Cumulus guide, short-reach optics typically transmit ~0.6–1.0 mW and work with Rx above ~0.05 mW (≈ −13 dBm). Always use the module's own alarm/warning thresholds (ethtool -m, mlxlink -m). DDM readings are typically accurate to about ±10%.

Live link checks

$ ibstat                     # per port: State Active, Physical state LinkUp, Rate 400
$ iblinkinfo                 # every link in the fabric: width and speed, spot 1X or slower links
$ mlxlink -d <dev> -m        # module info: vendor, part number, DDM per lane
$ mlxlink -d <dev> -c        # counters and BER (raw/effective)
$ perfquery                  # SymbolErrorCounter, LinkDownedCounter, PortRcvErrors …
$ ibdiagnet                  # fabric-wide check: links, speeds, errors, cable info
$ nv show interface swp1                 # admin/oper state, speed
$ sudo l1-show swp1                      # module → config → operational → firmware diagnosis
$ nv show platform transceiver swp1      # vendor, part number, DDM per lane
$ ethtool -m swp1                        # EEPROM + DDM with thresholds
$ ethtool -S swp1 | grep -i err          # uncorrected errors (post-FEC)
$ sudo l1-show swp1 --pcs-errors         # FEC-corrected errors

NVIDIA or not?

  1. Read the identityVendor name and part number from the module EEPROM (mlxlink -m, ethtool -m, switch transceiver show). NVIDIA/Mellanox parts carry OPNs like MCP…, MMA…, MMS….
  2. Compare to the validated listFor the exact NIC/switch firmware. Third-party parts may work but come with no performance guarantee.
  3. Run CVT / ibdiagnetFabric-wide: wrong cable types, unexpected speeds/widths, mismatched ends, and links that don't match the topology file.

Exam traps

  • Using the OTDR for loss acceptance.The OLTS (source + meter) measures insertion loss. The OTDR finds where events are.
  • Checking one lane.Parallel optics have 4 or 8 lanes. Check Rx power on every one.
  • "Rx power is fine, so the fiber is fine."A dirty end-face can leave power in range while errors climb. Inspect and clean anyway.
  • Skipping the reference.Without referencing the meter through the test cords, the loss number is meaningless.
  • "Link up = done."Also confirm the expected speed/width and zero or stable error counters.

Check yourself

1. Which tool measures the insertion loss of an installed fiber link for acceptance?

Insertion loss is measured with an OLTS against a reference. OTDRs locate events but shouldn't be used to measure cable loss.

2. Test wavelengths for single-mode fiber?

Single-mode: 1310 and 1550 nm (TIA-526-7). Multimode: 850 and 1300 nm (TIA-526-14).

3. An Rx reading is 0.5 mW. In dBm?

10 × log10(0.5) ≈ −3.0 dBm.

4. How do you tell whether an installed cable is an NVIDIA part?

The EEPROM identity (and label OPN) tells you the vendor and part. Third-party cables often link up too.

5. iblinkinfo shows one link at 1X width instead of 4X. Likely meaning?

A link that trains at reduced width or speed usually points to a physical problem on some lanes.
